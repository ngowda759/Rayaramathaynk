# Aaradhane Event Generator

## Overview

The Aaradhane Event Generator automatically creates and manages Guru Aaradhane events for the Sri Raghavendra Matha temple website. It uses Hindu Panchanga (lunar calendar) data to calculate the correct Gregorian dates for each Guru's annual Aaradhane.

## Key Design Principle

**Guru Parampara data is stored in Firestore** - This allows administrators to:
- Add/edit Gurus through the Admin UI
- Update lunar calendar dates (tithi, paksha, month) directly
- Enable/disable specific Aaradhanes
- Changes are automatically picked up by the next generation run

## Problem Statement

Guru Aaradhanes are celebrated annually based on the Hindu lunar calendar. The challenge is:
- Lunar calendar dates vary each year (different Gregorian dates)
- Manual event creation is error-prone and time-consuming
- 19 Aaradhanes need to be created/updated each year
- Sri Raghavendra Swamy has 3 separate Aaradhanes (Poorva, Madhya, Uttara)

### Firestore Data Source

The system reads from **Firestore** (not static files) for Guru Parampara data:

```
Collection: guruParampara
Document: aaradhanaes
└── gurus: [
    {
      id: "raghavendra-poorva",
      guruName: "Sri Raghavendra Swamy",
      aaradhaneTitle: "Sri Raghavendra Swamy Poorva Aaradhane",
      lunarMonth: "Vaishakha",
      paksha: "Krishna",
      tithiNumber: 13,
      tithi: "Trayodashi",
      durationDays: 3,
      raghavendraPhase: "Poorva",
      importance: "major",
      enabled: true
    },
    ...
  ]
```

**Benefits:**
- Admin can update lunar dates via Admin UI
- Add new Gurus without code changes
- Disable specific Aaradhanes temporarily
- Next generation run automatically picks up changes

## Key Components

### 1. Firestore Source (`lib/aaradhane/firestore-source.ts`)

Reads Guru Parampara configuration from Firestore:

```typescript
// Get all enabled Guru records
const gurus = await getGuruParamparaRecords();

// Check if data exists
const exists = await hasGuruParamparaData();
```

### 2. Panchanga Utilities (`lib/aaradhane/panchanga.ts`)

Loads pre-generated Panchanga data and matches lunar dates:

```typescript
// Load yearly Panchanga data
loadYearlyPanchanga(year: number): YearlyPanchanga

// Find Gregorian dates matching lunar criteria
findDatesForLunarDate(
  yearlyData: YearlyPanchanga,
  lunarMonth: string,
  paksha: "Shukla" | "Krishna",
  tithiNumber: number,
  durationDays: number
): string[]
```

### 3. Generator Service (`lib/aaradhane/generator.ts`)

Core logic for generating events:

```typescript
// Generate all events for a year (reads from Firestore)
const result = await generateAaradhanaeEvents(year);

// Validate generated events
const validation = validateGeneratedEvents(result, year);
```

### 4. Firestore Operations (`lib/aaradhane/firestore.ts`)

Safe Firestore updates with idempotency:

```typescript
// Update Firestore (create/update/skip)
const updateResult = await updateFirestoreEvents(
  generatedEvents,
  year,
  true // updateExisting
);
```

## Firestore Schema

### Guru Parampara Collection (Source Data)

```typescript
interface GuruParamparaRecord {
  id: string;                    // Unique ID (e.g., "raghavendra-poorva")
  guruName: string;              // "Sri Raghavendra Swamy"
  aaradhaneTitle: string;       // "Sri Raghavendra Swamy Poorva Aaradhane"
  paramparaNumber: number;       // Position in guru lineage (1-17)
  lunarMonth: LunarMonth;       // "Vaishakha", "Jyeṣṭha", etc.
  paksha: Paksha;              // "Shukla" | "Krishna"
  tithiNumber: number;          // 1-30
  tithi: Tithi;                // "Trayodashi", "Ekadashi", etc.
  durationDays: number;         // 1-3 days
  raghavendraPhase?: Phase;    // "Poorva" | "Madhya" | "Uttara"
  importance: "major" | "minor";
  enabled: boolean;            // Whether to generate this event
  description?: string;
}
```

### Events Collection (Generated Events)

```typescript
interface FirestoreEventDocument {
  // Basic event info
  title: string;
  description: string;
  location: string;
  
  // Dates
  startDate: Timestamp;
  endDate: Timestamp;
  
  // Display
  featured: boolean;
  published: boolean;
  status: EventStatus;
  
  // Classification
  category: "Aaradhane";
  guru: string;
  
  // Auto-generation tracking (safety)
  autoGenerated: boolean;        // TRUE = created by this system
  year: number;
  paramparaNumber: number;
  raghavendraPhase?: "Poorva" | "Madhya" | "Uttara";
  lunarCalendar: {
    lunarMonth: string;
    paksha: string;
    tithi: string;
    tithiNumber: number;
  };
  
  // Timestamps
  createdAt?: Timestamp;
  updatedAt?: Timestamp;
}
```

## Safety Features

### Idempotency
- Events are identified by `eventKey` (guru ID + year)
- Running the generator multiple times NEVER creates duplicates
- Existing events are updated, not recreated

### Manual Event Protection
```typescript
// ONLY update documents where autoGenerated == true
if (existing.autoGenerated && existing.year === targetYear) {
  await updateEvent(existing.id, newData);
}
```

### Validation
- All generated events are validated before Firestore update
- Checks for missing Raghavendra phases
- Detects duplicate event keys
- Verifies year matches

## GitHub Actions Workflow

### Schedule
Runs every January at 9:00 AM IST (03:30 UTC)

### Manual Trigger
Available via GitHub Actions UI with inputs:
- `year` - Target year (default: next year)
- `dry_run` - Don't update Firestore

### Process
1. Checkout code
2. Setup Node.js 20 and Python 3.11
3. Install dependencies
4. Check/generate Panchanga data
5. Seed Guru Parampara to Firestore (if needed)
6. Generate Aaradhane events
7. Update Firestore
8. Print summary

## Manual Execution

```bash
# First time setup - seed Guru Parampara data to Firestore
npm run seed:guru-parampara

# Generate events for next year

npm run generate:aaradhane -- --dry-run --year 2027
```

## Maintenance

### Adding a New Guru
1. Go to Admin > Settings > Guru Parampara
2. Add new Guru with lunar calendar data
3. Save changes
4. Next generation run will automatically include the new Guru

### Updating Lunar Dates
1. Go to Admin > Settings > Guru Parampara
2. Edit the Guru's lunar calendar data
3. Save changes
4. Next generation run will use the updated dates

### Disabling an Aaradhane
1. Go to Admin > Settings > Guru Parampara
2. Set "enabled" to false for the Guru
3. Save changes
4. Next generation run will skip this Guru

### Panchanga Data Generation
If Panchanga data is missing:
```bash
# Generate for a year
python scripts/generate_panchanga.py
```

The GitHub Actions workflow will also generate Panchanga if missing.
