## 2. Steps to start work in a fresh session without re-explaining anything

1. Open the repository root in Claude Code. The project memory for this folder already carries the
   three standing rulings (where the orchestrate and delegate skills live, launch workflows only from
   the repo root, HTML here uses the site's theme and never the CoreFlex one).
2. Say what you want. The skill triggers on questions about the app; for change requests it hands
   back the file list and the "How to change it" recipe, and AGENTS.md's planning phase applies.
3. If the question is about something built after the last refresh date at the top of
   `MIND-MAP.md`, run the refresh in section 4 first, or say "answer from the code and update the
   brain" and the skill will do that for the one module.

## 3. How the knowledge was produced, in one paragraph

Fifteen modules were analysed in parallel on 2026-09-19 by one Opus-high analyst each, writing from
the code rather than from the existing docs. A second, separate Opus-high agent per module then
tried to refute every claim against the code and corrected the file in place; across the run they
refuted 15 percent of sampled claims and fixed 80 broken path references. The router, the overview
documents, the HTML brief, the fault register and the redesign plan were then synthesised from the
corrected brain files, and each of those was reviewed by its own skeptic. A closing wave added the
field catalogue and closed the gaps the reviewers found. Every claim carries a `path:line`; every
agent's brief and every skeptic's report is kept under `.claude/state/`. Cost: 46 agents, about ten
million subagent tokens, three hours.

## 4. How to refresh after the code changes

1. Regenerate the inventory: `node .claude/state/inventory/inventory.mjs` from the repo root.
2. Measure the delta since the last refresh. The script used on 2026-10-18 compared two folders; on
   a git clone, `git diff --stat <last-refresh-commit> HEAD` gives the same list. Write the changed
   files per module to `.claude/state/delta/<date>/delta.json` (shape: `perModule.<id>.{added,deleted,modified}`).
3. Run `.claude/state/briefs/REFRESH.brief.md` for every module with changes, then
   `VERIFY.brief.md` for the ones with five or more changed files, then
   `SYNTH-REFRESH.brief.md` roles A and B. The Workflow script that did this on 2026-10-18 is
   `.claude/state/temple-portal-brain-refresh.workflow.js`; re-run it with today's date in `args`.
4. Update the date line at the top of `MIND-MAP.md` and append the run to `CHECKPOINT.md`.

A single module can be refreshed alone by dispatching one agent with the REFRESH brief and that
module's id; the brief tells it where everything is.
