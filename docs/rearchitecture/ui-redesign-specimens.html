Temple portal — proposed UI primitives

Specimens for the redesign described in UI-REDESIGN-PLAN.md. Every colour here is a token already declared in app/globals.css; nothing new was introduced. Typography, spacing, shape, elevation and motion are the proposed values.

This page deliberately shows the temple site's proposed look and is styled with the temple portal's own palette tokens from app/globals.css. No external fonts, scripts or images are loaded — the serif degrades to Georgia and the UI face to Segoe UI / system-ui.

Buttons

One component, six variants, four sizes. Dark ink on gold is what makes the primary action legible without changing a colour value.

Read the full plan

Primary = --primary fill + --foreground ink, 7.10:1. Destructive = --destructive + --primary-foreground, 5.38:1. Link = --temple-deep-red, 8.18:1.

The loading button keeps its label and locks its width; it never becomes the words "Please wait…". The disabled state is used when finance settings carry no UPI id.

Flat fill, one radius (8px), no gradient, no shadow, no transform. 44px tall so it clears every touch-target guidance. Labels name the outcome rather than the mechanism.

Inputs, select and textarea

Label above, hint below the label, error below the control. The resting border is --muted-foreground because --border is 1.44:1 against white and WCAG 1.4.11 asks 3:1 of a control boundary.

Motion

Four durations. Nothing animates on scroll, nothing loops except the skeleton's pulse, and prefers-reduced-motion removes the rest.

--motion-instant 120ms on colour and border only. --motion-enter 200ms for menus, sheets and toasts; --motion-exit 140ms; --motion-page 240ms opacity with no translation.

The skeleton's 1.6s opacity pulse is the one permitted loop, because it communicates a pending state rather than decorating one. The shimmer sweep in globals.css:613-617 is deleted.
