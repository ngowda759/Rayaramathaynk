## Seed-guard hardening (PR #363, commit 07e0b98)

- **Root cause / gap:** `scripts/seed-fresh-supabase.ts` `checkGuards()` claimed to
  "refuse production refs" but only matched `/prod|production|live/i`; it never
  consulted the approved project. So `--project-ref <approved> --yes-this-is-a-test-project`
  PASSED the guard, while `scripts/lib/guard-approved-project.mjs` treats that same ref as
  the one permitted target. The two guards disagreed and the approved (production) project
  was reachable via the seed CLI.
- **Fix:** fail closed on the approved ref — (a) `--project-ref` equal to
  `APPROVED_PROJECT_REF` refused; (b) URL match now uses the shared fail-closed
  `refFromSupabaseUrl` instead of substring `includes` (kills `supabase.co.evil.com` and
  `…supabase.co@evil.com`); (c) `--local` refuses a `DATABASE_URL` resolving to the approved
  project OR **ambiguous** (`analyzeDbUrlRef(...).ambiguous`) — Supavisor routes the tenant
  from the *username*, so ambiguity cannot be proven safe. Refusing the approved ref is a
  strict tightening: it's the production project and docs say there is no supported
  production seed path.
- **Key technical constraint:** **ts-jest CANNOT load `.mjs`** modules — `import … from
  "….mjs"` inside a `.ts` test fails with `SyntaxError: Cannot use import statement outside
  a module`, and a `transform`/`moduleFileExtensions` tweak does not fix it. Consequence: a
  unit test cannot `import { checkGuards } from "scripts/seed-fresh-supabase"` **once that
  script imports the `.mjs` library** (the import chain breaks test loading). Working pattern
  used: spawn the real CLI (`spawnSync("npx", ["--no-install","tsx", script, …])`) with a
  scrubbed env and `--dry-run`, and read `APPROVED_PROJECT_REF` via a `node --input-type=module`
  child process. Same convention as `tests/unit/supabase-diagnostics-migration-safety.test.ts`.
- **`scripts/lib/approved-project.d.mts`** (new) types the `.mjs` library; it also clears a
  pre-existing implicit-any error, so `tsc -p tsconfig.scripts.json` went 68 → 67 errors
  (baseline errors remain elsewhere: `migrate-ai-analytics.ts`). Handy general fix for
  "Could not find a declaration file for module '*.mjs'".
- **Push gotcha:** the token embedded in `origin`'s URL is **expired** — `git push origin …`
  hangs at a `Password for 'https://ghu_…@github.com':` prompt. Use
  `GIT_TERMINAL_PROMPT=0 git push "https://${GITHUB_TOKEN}@github.com/ngowda759/Rayaramathaynk.git" HEAD:<branch>`.
