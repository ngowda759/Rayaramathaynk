## F-A16 remediation (PR #382, branch `security/f-a16-production-remediation`)

Task: correct F-A16-02, prepare F-A16-01, review F-A16-03, PR only, no production ops.

- **F-A16-02 correction.** The old revision used the GLOBAL
  `ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC`. The 2026-11-03 audit
  found **0 global default ACL entries**, so it had nothing to revoke and would only *create*
  a global entry (defaults for `storage`/`graphql`/`graphql_public`). Removed; every statement
  now `IN SCHEMA public`. The implicit PUBLIC EXECUTE residual is closed **forward** by a new
  event-trigger guard (`20261114990000_f_a16_public_function_execute_guard.sql`) instead.
- **Removing source (b) from discovery.** An earlier revision also enumerated
  `has_schema_privilege(r.oid,'public','CREATE')` holders. That *widened the fail-closed set*
  (aborts on a role the applier cannot act for) without closing the residual — a per-schema
  `REVOKE … FROM PUBLIC` on FUNCTIONS is a **no-op** (per-schema defaults can only add, never
  subtract from the global default). Removed; discovery is now `pg_default_acl` for `public`,
  no grantee filter, fail closed per owner. Effective-CREATE enumeration deferred to owner-run.
- **The 0c check (public-facing role holding CREATE) stays** — it uses `has_schema_privilege`
  and is the one legitimate use of it in the migration.
- **F-A16-01** is now a narrow catalog-driven migration revoking only `TRUNCATE`/`REFERENCES`/
  `TRIGGER` (the three RLS cannot compensate for) from `anon`/`authenticated`/`service_role`.
  `service_role` keeps `TRUNCATE` on the 9 tables with a `BEFORE TRUNCATE` guard, read from
  `pg_trigger` (`tgtype & 2` = BEFORE, `tgtype & 32` = TRUNCATE). **DML revokes stay deferred**
  with a matrix + open question (more non-`false` SELECT policies exist than the 4 audited
  public-read tables: `temple_areas`, `announcements`, `ai_knowledge`, `featured_content`).
- **F-A16-07** (new): `PUBLIC` EXECUTE on `rls_auto_enable` / `update_updated_at_column` is
  *unnecessary* (trigger machinery runs as owner, doesn't consult session EXECUTE) but not
  exploitable; recommended SQL documented, **not** applied (pre-existing non-F-A16 objects).

## F-A16 PR #382 — second review pass (service_role TRUNCATE + replay fidelity)

- **Material inconsistency fixed.** F-A16-02 still left `service_role` with `TRUNCATE`
  on *future* tables while the corrected F-A16-01 revoked `TRUNCATE` from `service_role` on
  *existing* tables — a new table would be broader than an existing one. Section 1 now
  revokes `TRUNCATE, REFERENCES, TRIGGER` (canonical ordering) and the same set is used in
  the owner-run file, the post-conditions, the plan, the matrix and the checklists.
- **Ordering convention: `TRUNCATE, REFERENCES, TRIGGER`** everywhere (was a mix of
  `TRIGGER, REFERENCES` and `TRUNCATE, TRIGGER, REFERENCES`). Unit + db tests updated.
- **`f-a16-least-privilege-defaults.test.ts` TRUNCATE-token guard** counted 5 TRUNCATEs vs 2
  REVOKE matches because the post-condition's `privilege_type IN ('TRUNCATE', …)` literal
  also matched. Fix: strip `--` comments **and single-quoted literals** before counting, so
  only the REVOKE privilege list matches.
- **Real regression caught by the full-replay `tests/db/fresh-seed.test.ts`.** The new
  F-A16-01 post-condition clause (c) asserts the four public-read tables keep anon/
  authenticated SELECT. `fresh-seed.test.ts` had its **own** local `SUPABASE_ROLES_SQL`

  the migration aborted. **Root cause: the replay was not faithful to production.** Fix:
  export `SUPABASE_ROLES_SQL` from `tests/db/harness.ts` and import it in `fresh-seed.test.ts`
  (single source of truth) instead of duplicating a weaker copy.
