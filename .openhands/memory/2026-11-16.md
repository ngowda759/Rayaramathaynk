## The migration cast gotcha (cost a CI cycle)

`staff.auth_user_id` is `uuid`; `staff.firebase_uid` is `text`. `SET auth_user_id = firebase_uid` fails
with **"column auth_user_id is of type uuid but expression is of type text"** — caught by the PGlite
**database tests** (`npm run test:db`, jest.db.config.ts), which run *all* migrations. Fix:
`firebase_uid::uuid`, safe because the `WHERE … ~ '<uuid-regex>'` already restricts to UUID-shaped text.
Lesson: after adding a migration, run `npm run test:db` locally before pushing — the unit suite does not
apply migrations, so only the db suite catches this.
